# DNS 区域审定台（离线编制 / 复核 / 发布）

面向离线内网环境的 DNS 区域文件 Web 审定台。运维人员在浏览器中编制区域与
NS / A / AAAA / CNAME / MX / TXT 记录，暂存草稿，发布前整体验证；
修订版必须由**另一个账号**复核通过后才能发布，发布生成符合 BIND 语法的区域文件与
递增的 SOA 序列号，并可随时下载与回滚。

技术栈：**Node.js (Express) + React (Vite) + SQLite (better-sqlite3)**，单容器部署。

---

## 一键启动（Docker Compose）

```bash
docker compose up -d --build
```

启动后访问：

- **地址：** http://localhost:8080
- **端口：** `8080`（主机侧可在 `docker-compose.yml` 的 `ports` 中修改）

容器首次启动会自动完成：

1. 安装全部依赖（镜像构建阶段）；
2. 在持久化卷 `/data` 中创建 SQLite 数据库 `app.db` 并初始化全部表结构；
3. 写入三个初始本地账号。

数据持久化在 Docker 卷 `dns-console-data`（容器内 `/data`），删除容器不丢数据；
删除卷才会清空。

停止 / 查看日志：

```bash
docker compose down
docker compose logs -f
```

## 本地（无 Docker）运行

需要 Node.js 20+。

```bash
# 1. 安装依赖（根目录 + client）
npm run install:all

# 2. 构建前端
npm run build

# 3. 启动（启动时自动建库初始化）
npm start
# 访问 http://localhost:8080
```

开发模式（前端热更新，:5173 自动代理 /api 到 :8080）：

```bash
npm run dev:server    # 终端 1
npm run dev:client    # 终端 2，访问 http://localhost:5173
```

## 使用流程（四眼原则）

1. **编辑员**新建区域（区域名、主 DNS、管理员邮箱、初始顶点 NS），创建时即整体验证。
2. 在区域详情中增删 NS/A/AAAA/CNAME/MX/TXT，随时点「整体验证」；「暂存草稿」
   不要求通过验证，可反复保存。每次保存生成新的修订版号。
3. 页面右侧实时展示**相对现行发布版的记录差异**（新增绿色、删除红色，含区域头变更）。
4. **复核员**（必须与编辑者不同的账号）登录同一修订版，填写意见后「复核通过」。
5. **编辑员 / 管理员**点「发布」（复核员无发布权限；编辑者可以发布，但不能复核自己的修订）：
   - 发布时再次整体验证，**验证失败会定位到具体记录与原因，且绝不替换现行文件**；
   - 校验通过且存在编辑者以外账号的有效复核后才发布；
   - 生成 BIND 区域文件，SOA 序列号按 `YYYYMMDDnn` 递增。
6. 历史版本可「下载 .zone」或「回滚」。回滚会以旧版本内容创建新的回滚草稿，
   仍须另一账号复核后发布；**回滚发布产生比旧序列号更大的新序列号**。
7. 管理员可在「审计历史」查看仅追加、不可修改的完整操作流水。

> 四眼规则口径：一条修订版需要由 **`created_by` 之外的另一名用户**给出
> 「复核通过」，之后任意具备发布权限的账号（通常仍是编辑者本人或管理员）均可发布。
> 典型操作：`editor` 编辑并暂存 → 退出后用 `reviewer` 登录复核通过 → 再用
> `editor`（或 `admin`）登录发布。

## 编辑 / 复核失效 / 冲突规则

- **编辑使复核失效：** 修订内容一旦再次保存，会产生新的修订版，原修订版上的
  复核记录自动标记为失效（数据库触发器保证），新修订版必须重新复核。
- **过期修订提交冲突：** 若你打开页面后草稿已被他人更新（或复核后内容被改动），
  暂存 / 复核 / 发布会收到 **409 冲突**，系统不会覆盖远端版本；页面提示后
  重新加载即可。发布请求携带 `revisionId` 与 `contentHash` 做乐观并发检查。
- **发布验证失败：** 返回 422 与逐记录错误（记录 ID / 行号 / 字段 / 原因），
  现行已发布文件与序列号完全不变。

## 验证规则

- 记录名必须属于本区域（`@` 表示顶点，支持 `*.name` 通配标签）；
- 顶点至少一条 **NS**；
- 同一属主名下 **CNAME 不得与任何其他类型共存**，且 CNAME 唯一、不得位于顶点；
- **TTL** 必须为正整数（≤ 2147483647）；
- **A** 为合法 IPv4（拒绝前导零），**AAAA** 为合法 IPv6（支持 `::` 压缩与末尾内嵌 v4）；
- **MX** 仅允许顶点，优先级为 0–65535 整数，目标为 FQDN；
- NS / CNAME / MX 目标必须为以点结尾的完整域名（CNAME 允许 `@` 指向顶点）；
- 区域名、主 DNS 为合法域名，管理员邮箱为 `name@domain`（写入 SOA RNAME 时
  本地部分的 `.` 转义为 `\.`）；
- 完全重复的记录（名称/类型/值/优先级/TTL 全同）将报错。

## 生成文件与不可变性

- 区域文件只在**发布成功的事务内**生成并写入 `published_versions` 表，含
  `$ORIGIN`、`$TTL`、SOA（serial/refresh/retry/expire/minimum）及排序后的记录，
  TXT 按 RFC 1035 转义并按 255 字节分块；
- 已发布版本与审计日志**只追加、不更新、不删除**（应用无任何修改接口），
  下载永远返回发布时落库的原始文本；
- 文件名：`<区域名>-<序列号>.zone`。

## 目录结构

```
server/            Express API、SQLite 初始化、校验、区域文件生成
  index.js         路由与发布/回滚/冲突事务
  db.js            表结构、会话存储、初始账号、审计写入
  validate.js      DNS 记录整体验证（IP/域名/共存/TTL/MX…）
  zonefile.js      BIND 文件渲染、SOA 序列号、差异比较、内容哈希
client/            React + Vite 前端（src/pages、src/components）
Dockerfile         多阶段构建（前端构建 → 后端运行镜像）
docker-compose.yml 一键启动，卷持久化 /data
```
